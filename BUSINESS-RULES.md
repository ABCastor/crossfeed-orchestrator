## BR-DATA-001 — Routes must refuse material above their data policy [DECIDED · supplied r19/model-refresh brief, 20 Oct 2026; code class owner-decided 20 Oct 2026]

- RULE: Task material has three classes, from least to most sensitive: `public`, `code` (private project source code and its docs, with no notes, memory, personal or client data, or secrets) and `private` (everything else). Each lane may declare `data_policy: public-only | code-ok | private-ok`: public-only accepts public material, code-ok accepts public and code, private-ok accepts all three. Free promotions default to public-only. Unknown task material defaults to private. Automatic selection, routing and explicit execution must refuse material above the lane's policy: private on public-only and code-ok lanes, code on public-only lanes. Only the owner can approve code-ok or private-ok for a model. Moving a lane to code-ok is the owner's recorded decision that a free model may see his project code (accepting the risk that it lands in training data); it never extends to notes, memory, personal or client data or credentials, which are private. Public classification covers the complete prompt, context, attachments and tool inputs; it cannot grant access to a private workspace. Public-only OpenCode execution therefore uses the existing tool-less `--direct` path. A code-ok lane may read the project workspace the caller points it at, so it does not require `--direct`; the caller is responsible for pointing it at code only.
- Authority: point 4 of the supplied brief explicitly requires this field, a private-material refusal and owner control of private-ok. Existing non-promo lanes retain private-ok behavior when the field is absent; newly discovered unverified lanes default to public-only. The code class and code-ok policy come from the owner's 20 Oct 2026 decision (free OpenCode promo models may work on private project code; never notes, memory, personal or client data, or credentials).
- implemented-by: `scripts/data_policy.py:refusal`, `scripts/fleetctl.py:choose_lane`, `scripts/fleetctl.py:acquire_lease`, `scripts/selector.py:enumerate_options`, `scripts/selector.py:_command`, `scripts/roster.sh:check_lane`, `scripts/opencode-agent.sh:lane_setup`.
- tested-by: `tests/test_business_model_refresh.py:RefreshTests.test_policy_refuses_private_routing_selector_and_explicit_acquisition`, `test_code_class_ordering_across_lane_policies`, `test_code_ok_lane_routes_code_but_not_private_and_public_only_refuses_code`, `test_wrapper_code_ok_lane_runs_without_direct_and_refuses_private`; permitted controls `test_public_control_and_per_model_owner_override`, `test_public_wrapper_uses_empty_working_root_and_private_is_refused`, and `test_free_promo_candidate_does_not_borrow_operational_admission`.
- Review when: a transport proves a different public-material confinement boundary, the owner changes a model's data-policy approval, or a code-ok lane is seen reading anything but project code.

## BR-SWITCH-001 — Agents control the fleet within owner limits [DECIDED · owner instruction 20 Oct 2026]

- RULE: Agents may change levels, switches, model toggles, model choices and managed pins. They may enable and raise agent-set restrictions. They must not enable a model switched off by the owner or raise a level above the owner's current ceiling. Turning off or lowering is always allowed. A later agent restriction must preserve the owner's ceiling until the owner replaces or releases it. The owner can always change controls, subject to existing model admission and retirement rules.
- Authority: the owner said, “Of course they can switch whatever they want, they have full control of crossfeed orchestrator. It's just if I put something to off, for example, they would leave it there. So it would be recorded if something was switched by me or by an agent.” Supplied r21/switch-actor brief explicitly extends this to owner-lowered levels.
- Attribution: console actions and an explicit `--owner` instruction record `owner`; CLI actions otherwise record `agent`. Every control write records time and an optional short reason beside state, with compact append-only history. Unattributed legacy state remains unknown. Console labels latest actor and local time; owner protection is retained separately so an agent cannot erase it by reasserting off.
- implemented-by: `scripts/fleetctl.py:check_control`, `record_control`, `set_pool_level`, `set_model_toggle`, `set_model_choice`, `apply_profile`, `sync_pins`; `scripts/console.py:Console.set_level`, `set_toggle`, `set_choice`, `set_preference`, `_control_text`; `scripts/hooks/model-switch-guard.py:check_switch_change`, `strip_redirections`.
