Scope: the Benchmarks page and local admission-check policy, the opt-in paid MiMo lane, the optional Haiku judgment-refusal policy, local fit-evidence imports, the proposed OpenCode Go value-routing policy, the daily catalog/data-policy rules, and the OpenCode v2 worker boundary below. This ledger claims conformance only for rules listed here — it is NOT a claim of repo-wide coverage.

- RULE: Do not start new broad local benchmark campaigns. For each newly admitted model, run one small admission check using a handful of tasks on cheap lanes and keep a receipt. Run more local benchmarking only when the owner asks. Keep existing local results visible and labelled as ours.
- Authority: the owner agreed on 17–19 Oct 2026 to rely more on outside rankings and stop broad local tests, with one small check when a new model arrives. The check shape comes from the supplied task brief.
- implemented-by: `scripts/benchmark_page.py:render_body` (outside rankings first and small-admission-check copy) and `scripts/benchmark_page.py:nerd_panel` (outside readings before local results).

- Review when: the owner asks for more local benchmarking or changes the admission-check shape or receipt.

## BR-MIMO-002 — Reserve within a shared daily cap before sending [DECIDED · supplied lane brief]

- RULE: Pro and Flash share a provisional $5/day cap, configurable by the owner. Before each paid call, reserve its worst-case cost from live pricing. Concurrent/incomplete requests count against the same cap. Replace a reservation only with valid reported cost; missing usage, interruptions and ambiguous failures retain it. No automatic paid retries. Unexpected excess billing blocks future paid admission pending owner reconciliation.
- Authority: the lane brief requires a hard daily cap enforced before each call from live prices. Reservation and no-retry accounting implement that bound; they do not grant broader paid access. Reported costs belong to their local settlement day; unresolved calls remain reserved across resets.

## BR-EVIDENCE-001 — Local fit trials update outside priors with provenance [DECIDED · supplied Benchmarks brief, 15 Oct 2026]

- RULE: Mechanically checked fit-only benchmark passes and failures enter the selector's local ledger once per trial, retaining source and measurement date. Each trial contributes one Beta observation alongside the existing weighted external prior. Imports preserve other ledger observations and reject conflicting reimports. Held-out and excluded cells never train selector quality or telemetry; mixed fit/held-out quota batches supply no inferred fit cost. Missing measurements remain unknown. Artificial Analysis values remain host-local runtime data and must never be copied into published source files.
- Authority: the supplied Benchmarks task explicitly requests sample-size weighting, provenance, no silent prior replacement and runtime-only AA numbers; the existing `docs/SELECTOR.md` and frozen `bench/split.py` define the fit/held-out boundary.

## BR-DATA-001 — Public-only routes must refuse private material [DECIDED · supplied r19/model-refresh brief, 20 Oct 2026]

- RULE: Each lane may declare `data_policy: public-only | private-ok`. Free promotions default to public-only. Unknown task material defaults to private. Automatic selection, routing and explicit execution must refuse private material on public-only lanes. Only the owner can approve private-ok for a model. Public classification covers the complete prompt, context, attachments and tool inputs; it cannot grant access to a private workspace. Public-only OpenCode execution therefore uses the existing tool-less `--direct` path.
- Authority: point 4 of the supplied brief explicitly requires this field, a private-material refusal and owner control of private-ok. Existing non-promo lanes retain private-ok behavior when the field is absent; newly discovered unverified lanes default to public-only.
- implemented-by: `scripts/data_policy.py:refusal`, `scripts/fleetctl.py:choose_lane`, `scripts/fleetctl.py:acquire_lease`, `scripts/selector.py:enumerate_options`, `scripts/selector.py:_command`, `scripts/roster.sh:check_lane`, `scripts/opencode-agent.sh:lane_setup`.
- tested-by: `tests/test_business_model_refresh.py:RefreshTests.test_policy_refuses_private_routing_selector_and_explicit_acquisition`; permitted controls `test_public_control_and_per_model_owner_override`, `test_public_wrapper_uses_empty_working_root_and_private_is_refused`, and `test_free_promo_candidate_does_not_borrow_operational_admission`.
- Review when: a transport proves a different public-material confinement boundary or the owner changes a model's data-policy approval.

## BR-OPENCODE-WORKER-001 — Preserve the worker boundary during the v2 port [DECIDED · owner brief supplied 20 Oct 2026]

- RULE: Read-only OpenCode workers deny writes, shell execution, nested agents and external-directory access. Write workers require explicit --write and a clean git worktree, retain external-directory and nested-agent denials, and run in caller-owned isolation. Direct calls expose no tools or project context. Every run uses a private server and state. The port must not edit live owner configuration.
- Authority: supplied r18/opencode-v2 brief, goals 1, 2 and 4; existing isolation and lane contracts. This records supplied policy, without granting a new write, spend or deployment permission.
- implemented-by: `scripts/opencode-agent.sh:main`, `scripts/opencode_v2.py:worker_config`, `scripts/migrate_opencode_v2.py:main`.
- tested-by: `tests/test-opencode.sh:test_v2_boundary` (read-only prohibition, persisted write control, external denial in build, direct and shared boundaries), `test_write_cleanliness_gate`, `test_v2_account_snapshot`; `tests/test_opencode_v2.py:test_no_external_plugins_skills_or_mcp_in_lean_and_direct`, `test_profile_imports_only_named_instructions_and_shared_skill_paths`, `test_migration_cli_writes_separate_candidates_for_both_config_formats`. Boundary execution uses an independent rule-evaluating test double; native v2 acceptance is explicitly unverified where a sandbox prevents server binding.
- Review when: OpenCode changes tool names, permissions, discovery, auto-approval or standalone semantics.
