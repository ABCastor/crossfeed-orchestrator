# Crossfeed measurement suite

This suite measures coding CLI options on generated tasks, then compares routing policies by looking up their choices in the same outcome grid. It uses Python 3.9+ and the standard library. Generation, checking, reference verification and statistical evaluation run offline; the grid launches only the commands you configure.

## Try it offline

From the repository root:

```sh
python3 -m unittest discover -s bench/tests -v
python3 bench/smoke.py --out smoke-output
```

The smoke command generates seeds 1 and 2, calls the checker on all 96 reference solutions and all 96 empty replies, executes a 192-cell grid using an offline reference worker and an empty worker, verifies resume, and writes `verification.json`, `evaluation.md` and `evaluation.json`. It uses 10,000 bootstrap resamples by default. Its token counts, prices and quota usage are synthetic. These artifacts test the machinery; they say nothing about model quality.

The output directory must be empty. For faster development, `--resamples 100` is available.

## Generate and check tasks

```sh
python3 bench/generate.py --seed 1 --out tasks/fit
python3 bench/generate.py --seed 2 --out tasks/heldout
python3 bench/check.py tasks/fit/fix-1 tasks/fit/fix-1/reference/workspace tasks/fit/fix-1/reference/reply.txt
```

Each default seed contains 48 tasks: eight each for fix, implement, review, repo-qa, reasoning and extraction, with two easy, two medium, two hard and two expert in each family. Each task contains:

| Path | Purpose |
|---|---|
| `PROMPT.md` | Instructions the worker receives |
| `workspace/` | Public fixture files copied to the worker |
| `meta.json` | Family, template ID, tier, difficulty (same as tier) and generation seed |
| `check.json` | Hidden expectations and tests |
| `reference/workspace/`, `reference/reply.txt` | Generated reference solution |

The runner copies only the public workspace and prompt. References are generated by code, without a model. [reference/README.md](reference/README.md) explains how to materialize them separately.

Fix checks require the original tests to remain byte-identical, reject added or deleted test files, and run trusted tests. Implementation checks insert hidden unittest code only into a temporary check directory. Both also compute candidate values in a separate process; the parent compares values, types and input mutation against hidden expectations, so disabling unittest assertions cannot fake a pass. Public fix tests expose a small regression sample; hidden scoring includes distinct inputs, so a lookup of published answers cannot pass. JSON diff checks also reject mutable output containers shared with either input. Code-family workers must also return a nonempty reply. Review replies end with `{"bug_file":"relative/path.py","bug_line":12}`; the new-file line number must be within one of the planted defect. Repo questions and reasoning replies end with `{"answer":...}`. String answers ignore case, outer whitespace, and whitespace beside commas or colons; integers must be JSON integers. Extraction requires a whole JSON object, with exact values and types for the checked fields. Extra top-level extraction fields are ignored. Duplicate JSON keys, nonfinite values and workspace symlinks are rejected.

`check.py` always prints one JSON line containing `pass`, `reason`, `strict_pass` and `format_ok`, and exits zero, including invalid submissions. Consumers must inspect `pass`. For repo-qa, reasoning and review, the last complete line that parses as a JSON object supplies the answer. Prose braces and earlier object lines are ignored. Non-whitespace after the selected line makes `format_ok` false; `strict_pass` requires both correct content and correct format. Extraction retains whole-object or single-fence recovery, with ambiguous objects rejected. Duplicate keys and nonfinite values never form a valid object line. `format_issue` records `fenced` or `extra prose` when the requested form was missed. A trailing Crossfeed receipt is removed before either verdict.

For larger held-out sets:

```sh
python3 bench/generate.py --seed 3 --per-family 32 --out tasks/heldout-large
python3 bench/verify.py --out verification/brief2 --per-family 32
```

Generation cycles through easy, medium, hard and expert, so tier counts differ by at most one for any positive `--per-family N`. Template selection rotates across the tiers: 16 tasks cover all four templates at all four tiers, and 32 tasks cover each pairing twice, producing 192 tasks per seed. Growing N preserves the first N fixtures. Each task has its own seeded random stream. The verification command generates seeds 1 and 2, checks all 384 references and empty replies, verifies coverage and regenerates each seed to compare file hashes.

Every family has four different task templates. Easy tasks isolate one rule; medium tasks combine rules; hard tasks add state, indirection or boundary interactions; expert tasks combine several invariants or longer evidence trails. Expert fixes span multiple files. Difficulty describes the intended challenge. Frontier pass rates and the intended under-ten-minute solve time still need a real model pilot. Do not infer calibration from reference passes.

| Family | Templates |
|---|---|
| Fix | Pagination, interval merging, cache invalidation, recursive parsing |
| Implement | Tokenizer, LRU cache with TTL, graph planning, nested JSON diff |
| Review | Ranked feed, civil time, memo coherency, retry scheduling |
| Repo QA | Config precedence, plugin dispatch, scoped injection, route features |
| Reasoning | Lineup constraints, corrected production arithmetic, resource scheduling, portfolio selection |
| Extraction | Purchase order, shipping manifest, experiment report, incident chronology |

Fixture expectations and reference implementations are generated locally. This revision changes fixture contents and digests, so start a fresh campaign rather than resuming a grid generated by the earlier suite.

## Configure the grid

[options.example.json](options.example.json) shows verified flag shapes for Codex, Claude Code, Antigravity and OpenCode wrappers. Set `CROSSFEED` to the orchestrator root, copy the example to your campaign directory, and replace model choices and null prices with the admitted options and prices you intend to measure. This suite does not discover live quotas or prices.

```sh
python3 bench/run_grid.py --tasks tasks --options bench/options.example.json --out results.jsonl --dry-run
python3 bench/run_grid.py --tasks tasks --options campaign/options.json --out results.jsonl --parallel 2
python3 bench/run_grid.py --tasks tasks --options campaign/options.json --out results.jsonl --only review
```

`--dry-run` prints planned argv arrays, preserves environment-variable names, launches nothing and leaves the output untouched. Set required environment variables before actual execution. Commands may be argv arrays or shell-quoted argv strings; the runner splits strings into argv and never invokes a shell. Use [wrapper.py](wrapper.py) for Antigravity's prompt-text flag instead of shell command substitution.

Available template fields are `{prompt_file}`, `{workdir}`, `{model}`, `{level}`, `{bench_dir}`, `{reply_file}`, `{events_file}` and `{usage_file}`. Literal braces in a command must be doubled. Standard output is the final reply unless the command writes `{reply_file}`. Set `timeout_s` per option, default 600. The outer supervisor allows `termination_grace_s`, default five seconds, for cleanup after TERM. The example wrappers use `--kill-after 1` so their separate child groups finish cleanup within that grace. Custom commands that detach children must supervise those children themselves.

Each task/option pair gets a fresh temporary directory. `workspace_git: true` creates a clean temporary Git repository for OpenCode's write gate; it requires Git, while the Python suite itself has no package dependencies. This is **file isolation, not a security sandbox**: running arbitrary submitted Python or external CLIs needs the caller's sandbox. Use wrappers that confine edits and freeze their tool policies for a campaign.

Results include task ID (`seed:family-k`), family, difficulty, template ID and tier when present, seed, option, pool, model, level, pass/reason, worker duration, exit code, and fixture/option digests. Worker failure or timeout is recorded as a failure. A wrapper-reported model substitution or usage-sidecar identity mismatch is marked `excluded`; evaluation refuses it so another model's outcome cannot be mislabeled. Inspect and rerun excluded cells into a corrected campaign output. Only a trailing line beginning exactly `Crossfeed model receipt: ` is removed before checking; interior receipt-like text remains part of the answer. The stdout receipt is read even when the wrapper uses `{reply_file}`. Results retain the provider-reported model as `ran_on` and receipt UUID as `run_id`. After stripping the `opencode-go/` prefix from both IDs, a reported model differing from the requested option sets `excluded: true` and reason `receipt model mismatch`. A receipt that says the underlying model is unconfirmed records `identity: unconfirmed` and no `ran_on`; that cell remains eligible.

Resume skips completed task/option pairs and rejects changed fixtures, options, expanded command variables, or referenced Python/shell scripts. It cannot fingerprint every transitive CLI dependency, so retain the CLI and wrapper versions with campaign records. A `.lock` prevents concurrent writers to the same results file. After a hard kill, inspect the lock's PID before removing a stale lock. A truncated JSON line is reported for repair instead of silently discarded. Every result includes `cell_dir`, pointing to `<results dir>/cells/<task>__<option>/` (IDs are percent-encoded for paths). Each cell retains the original `reply.txt`, the last 4096 bytes of stderr in `stderr.tail`, and `receipt.json` with parsed identities and raw receipt lines for stdout and any separate final reply. These survive failures, timeouts and launch errors. Prompts, workspaces and hidden check data are not copied into cell directories. Keep separate campaigns in separate result directories to avoid overwriting cell evidence.

## Tokens and cost

The runner reads `{usage_file}` as a JSON object with optional `tokens_in`, `tokens_out`, `pool_percent`, `model` and `level`. Counts must be nonnegative integers; percent is a nonnegative finite share of the full pool allowance: `pool_percent: 25` means 25%, not 0.25%. The model and level, if supplied, must match the requested option. It also recognizes Codex `turn.completed` usage and OpenCode `step_finish` token events written to `{events_file}`. Unknown formats or missing events leave token counts absent. A malformed telemetry stream does not turn a correct answer into a failure; the result records a telemetry error and cost stays unknown.

Each option has `price_1m: {"in":...,"out":...}` in USD per million tokens. An optional top-level `prices` table keyed by option ID is also supported. API-equivalent cost is `(tokens_in * price_in + tokens_out * price_out) / 1e6`. OpenCode cached reads/writes count as input; Codex's reported input already includes cached input. OpenCode reasoning tokens count as output, matching its [token accounting](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/session.ts). This is a list-price proxy, not a subscription invoice; it does not apply cache discounts or infer quota consumption from tokens. Missing prices or counts produce unknown cost, never zero. Unknown cost also disables the fit hull and Zero baseline when the hull cannot be established.

## Evaluate policies

```sh
python3 bench/evaluate.py results.jsonl --policies campaign/policies.json --split heldout
```

The command prints Markdown and writes `results.summary.json`. Use `--json-out PATH` to choose the JSON destination, or `--json-out -` to print it after a delimiter. `--seed` defaults to 0 and `--resamples` defaults to 10,000.

[policies.example.json](policies.example.json) supplies the configuration shape. `options_file` and mapping filenames resolve relative to the policy file. Declare disjoint `fit_seeds` and `heldout_seeds`; choose `always_max`, `always_cheapest` and `fixed_seats` before measuring. The evaluator chooses `single-best` by highest fit pass rate only, breaking ties by option ID. It applies that choice unchanged to either requested split.

Add `selector` as a task-to-option mapping or a relative JSON mapping filename:

```json
{
  "selector": {"2:fix-1": "codex-high", "2:fix-2": "claude-high"},
  "selector_variants": {"alternative": "selector-alternative.json"},
  "number_variants": 2,
  "policy_seed": 0,
  "expected_task_ids": "preregistered-task-ids.json"
}
```

The snippet is a shape example, not a complete campaign. Supply a choice for every evaluated task. `expected_task_ids` is a list or relative JSON list filename containing the preregistered task IDs. Use it in real campaigns: checking only the row union cannot detect a task missing from every option. The legacy seed-split evaluator requires a complete measured grid for all configured options on fit and requested-split tasks, rejects inconsistent metadata/provenance, and never silently narrows a pair's task set. Prune the option list before measuring, rather than letting missing cells choose the comparison set.

In addition to the declared policies, evaluation includes every option as a fixed-level baseline, a seeded random-level baseline for each model, Zero as a seeded uniform mix over the upper cost-quality hull chosen on fit tasks, and the cheapest passing oracle. If no option passes a task, the oracle uses the cheapest failure. When an eligible option's cost is unknown, the oracle's minimum cost and cost regret remain unknown; its pass bound still exists.

Reports contain pass rate, mean API-equivalent cost, median/p90 latency, pass regret, signed cost difference against the oracle, measured per-pool percent, the share routed to `always_max` (collapse index), and the area under the observed upper cost-quality hull. Cost difference can be negative for a cheaper failure. Area uses trapezoidal interpolation over its stated cost range, without extrapolation; it is descriptive and changes if that range changes.

All policy pairs use the same task samples for seeded paired-bootstrap 95% intervals on differences, including latency and regret. McNemar reports the exact two-sided binomial p-value for discordant pass/fail outcomes. Selector-involving comparisons also receive Holm multiplicity correction; set `number_variants` to include every selector variant tried, including unreported variants and quota mappings. The intervals remain ordinary pairwise intervals, not simultaneous intervals. Task-level resampling treats generated tasks as sampling units; shared templates can correlate outcomes. These intervals do not establish generalization beyond this task suite or equivalence between policies.

Quota replay consumes externally supplied choices and measured pool percentages. It does not run or tune the selector. For example:

```json
{
  "quota_scenarios": [{
    "id": "near-critical",
    "selector": "selector-critical.json",
    "pools": {"codex": {"remaining_percent": 10, "reset_after_tasks": 12, "reset_allowance_percent": 100}}
  }]
}
```

An optional `task_order` lists every evaluated ID once; otherwise replay uses sorted IDs. Each configured pool can reset once, after the given number of tasks. The report records usage, allowance expired unspent at that reset, and overdraw. Missing usage stays unknown. Provide separate external maps for a pool near its guard and a pool about to reset with spare allowance. Generating those maps from a fit-only router, and confirming live quotas, belongs to the router campaign.


### Evaluate the preregistered task split

Use `--prereg` for campaigns whose fit/held-out split hashes the task folder name. Result IDs are `seed:folder`; the seed prefix is removed before SHA256, and an odd digest selects held-out. This mode reports held-out tasks only and fixes bootstrap and policy seeds at 7. The default is 10,000 resamples. Smaller `--resamples` values are useful for a plumbing check and are recorded in the output.

```sh
python3 bench/evaluate.py campaign/results-codex.jsonl campaign/results-claude.jsonl campaign/results-go.jsonl --policies campaign/prereg-policies.json --split heldout --prereg --tasks campaign/tasks --costs campaign/costs.json --json-out campaign/heldout.summary.json --svg-out campaign/cost-quality.svg
```

Build the selector's fit evidence in a separate levels file. The input state template is a copy of the router state with `selections/` omitted; the bridge creates temporary task states and calls the installed `fleetctl.py select` with `--no-refresh`.

```sh
python3 bench/to_evidence.py campaign/results-codex.jsonl campaign/results-claude.jsonl campaign/results-go.jsonl --split fit --levels-in campaign/state-template/evidence/levels.json --levels-out campaign/levels-fit.json
for scenario in now codex-tight claude-surplus go-tight; do
  python3 bench/selector_policy.py --results campaign/results-codex.jsonl campaign/results-claude.jsonl campaign/results-go.jsonl --state-template campaign/state-template --options campaign/options-codex.json campaign/options-claude.json campaign/options-go.json campaign/options-agy.json --scenario "$scenario" --out "campaign/policy-$scenario.json"
done
```

`now` preserves the copied quota snapshot, including its observation ages. The other scenarios set the affected pool to 95% used for tight or 5% used for surplus, halfway through its quota windows, and mark the source synthetic. They are replay scenarios, not live quota observations.

The evidence bridge's optional `--costs` accepts only fit-attributed reports. `python3 bench/cost.py campaign/results-codex.jsonl --split fit > campaign/costs-fit.json` supplies the `split=fit` provenance. A file mixing fit and held-out tasks cannot attribute its whole batch debit to the fit subset, so the report keeps fit costs unknown unless a fit-only quota manifest exists. Descriptive evaluation costs may cover the full measured batches; the fit-only restriction applies to costs used to tune the selector.

The policy file can merge option files from several lanes. Paths resolve relative to that file:

```json
{
  "split_method": "task-name-sha256",
  "options_files": ["options-codex.json", "options-claude.json", "options-go.json", "options-agy.json"],
  "expected_task_ids": "task-manifest.json",
  "selector": "policy-now.json",
  "selector_variants": {"codex-tight": "policy-codex-tight.json"},
  "number_variants": 4
}
```

`--tasks` reads `meta.json` from the frozen task folders so a task absent from every result file still appears in the report. A full `expected_task_ids` manifest also preserves absent tasks; use `--tasks` if an absent task's family cannot be recovered from its ID. Keep scarce options out of the main option files: the preregistration gives their fixed subset a separate report. For that separate report, include both main and scarce option/result files and set `heldout_task_ids` to a list or relative JSON list path containing the frozen subset. For this preregistration, that is the first 32 held-out tasks sorted by folder name, after removing the `seed:` prefix. Every requested ID must belong to the frozen held-out universe. The fit universe remains complete, while reported measurements and missing cells cover fit plus the selected held-out subset. Scarce options with no fit cells stay explicitly ineligible for single-best selection; their fixed-level baselines still report coverage and scores on the subset.

Task exclusions apply uniformly to fit evidence and every held-out policy. The evaluator reads `excluded-hook-tasks.txt` beside each result file and an optional policy `exclude_tasks_file` TXT path. Each line names a task folder, without its `seed:` prefix. Excluded folders leave the task universe, expected manifest, requested subset and missing-cell report before outcomes or provenance are validated. The summary retains their names, observed/declared IDs and the exclusion rationale. This implements the preregistration's hook-error amendment; those harness errors never become model failures.

The preregistered baselines are Opus 5.5 xhigh (`opus55-xhigh`) for always-max and DeepSeek V4.1 Flash high (`ds41-flash-high`) for always-cheapest. Fixed seats use Sol high for repair/implementation, Sol xhigh for review, and DeepSeek Flash high for repository questions. Reasoning and extraction also default to DeepSeek Flash high, an explicit assumption because the preregistration leaves those seats unspecified. Set `fixed_seats` for those two families before comparing if the campaign defines another choice. Every configured option appears as a fixed-level baseline; random-level samples uniformly within each canonical model. Provider prefixes and Gemini selectors that embed the level normalize through the evidence bridge's model key; an explicit option `model_key` can override that key.

Single-best uses fit outcomes only, with the same option applied to every held-out task. An option is eligible only when all its fit cells exist. Until every option is eligible, the choice is marked provisional. Zero needs a complete fit cost-quality hull; missing fit cells or unknown fit costs leave Zero unmeasured. Changing held-out passes or costs cannot change either fit choice.

Selector files may be a plain task-to-option mapping or the bridge's full document, `{"mapping": {"task": "option-or-null"}, "selections": {"task": {}}}`. In the actual mapping, use JSON `null` for an unmeasured choice. Missing choices and missing selected cells remain missing. They never count as failures or acquire guessed scores.

Partial-grid reports keep full-universe metrics unknown when required measurements are absent. Each policy includes measured coverage, missing IDs and a separate `measured_subset` score. Paired comparisons use the intersection of measured task outcomes and name every included and excluded task. These subset results are exploratory: interrupted lanes can change which tasks enter a comparison. Missing telemetry leaves the affected cost or latency statistic unknown. Oracle quality is known when any measured option passes; oracle minimum cost and its latency require every eligible option's measured cost.

`--costs` accepts `bench/cost.py`'s `crossfeed-quota-cost/v1` JSON, also configurable as `costs_file`. It applies each option/pool's measured binding-window debit per task as a batch average and retains the cost report's shared-pool warnings. Unknown debit stays unknown. This quota measure is separate from API-equivalent USD, which still requires token counts and prices. Reports include both total and mean debit per pool, plus paired intervals for each. Cost-quality area and the standalone SVG use only policies with complete held-out quality and USD measurements; an empty curve states that no complete measurements exist.

Keep output limits equal across levels and freeze any tuned router constants using fit data only. A 48-task set is useful for plumbing and large differences; it is too small to settle modest quality gaps.

## Mine real repairs

```sh
python3 bench/history.py --repo "$INPUT_REPO" --allow-repo "$INPUT_REPO" --out verification/history --since 2026-06-01 --max 10
```

Set `INPUT_REPO` to a repository you have permission to use as benchmark input. Repeat both `--repo` and `--allow-repo` for each additional repository. Unapproved or duplicate inputs are refused. Mining reads Git objects, builds filtered exports in scratch directories and writes only the output directory. `--max` limits candidate commits per repo, not accepted tasks; omit it for an exhaustive search. `--timeout` defaults to 90 seconds for each test invocation. `summary.json` records candidates, kept tasks and rejection counts; `progress.json` records partial counts during a run.

A `history-fix` candidate changes both tests and source. Its public workspace contains the parent's files with only the commit's test changes applied. The prompt names the tests and includes at most 60 lines of failing output. The saved `reference.patch` contains only non-test changes, and the reference workspace is constructed by applying that patch to the public workspace. Mining retains a task only after touched tests fail on the public tree and pass on that exact reference tree within the timeout. Python unittest and pytest, Node's test runner and Bash test scripts are supported; missing dependencies cause rejection, never installation. Standard credential paths, recognizable secret content, symlinks, Git metadata and ignored files are omitted. Exported and current repository ignore rules both apply conservatively. Exports over 50 MiB and commits whose filtered exports cannot be reconstructed by the patch are rejected.

History checks protect every exported test file by checksum and bytes. `scope_extra_files` lists edits beyond the reference patch's file set; those edits are measured rather than automatically failing a solution. Tests run in a separate copy with an isolated HOME and a timeout. Scope checks detect retained writes around that copy or the worker cell. They cannot detect every absolute-path write elsewhere on the host. A caller-enforced filesystem sandbox is required to establish the full no-outside-edits gate; snapshot checks alone do not establish it. The supplied input repositories must remain read-only at the operating-system level too.

Difficulty uses non-test changed lines and total files touched: easy is at most 20 lines and one file, medium at most 80 lines and three files, hard at most 250 lines and six files, and expert is larger. This is a size heuristic, not measured model difficulty.

## Observe subscription quota

```sh
python3 bench/run_grid.py --tasks verification/history --options campaign/options.json --out campaign/results.jsonl --pool-batches --usage-cmd 'python3 $CROSSFEED/scripts/fleetctl.py usage --json' --shared-pool opencode-go
python3 bench/cost.py campaign/results.jsonl
```

`--pool-batches` finishes one pool before the next. With `--usage-cmd`, the runner retains before/after snapshots for each pool and each option subbatch, so two options sharing a pool have distinct measured boundaries. Tasks within an option batch can run in parallel. Results point to both snapshot pairs and retain per-cell token telemetry. The usage command is parsed as an argv array, expands environment variables, and runs without a shell; `--usage-timeout` bounds it. Failed snapshots remain inspectable and yield unknown cost. Resume adds fresh batches only for unfinished cells.

`cost.py` reads the fleetctl usage schema and divides the observed binding-window delta by attempted tasks for each pool and option. It compares the same window, excludes non-binding windows and refuses cached, stale, reset, changed-bottleneck or mixed-option evidence. Missing measurements remain unknown. The unit is percentage points of the binding window per task. Shared plans add another user's consumption to the delta: identify them with `--shared-pool POOL` or `shared_pool: true` on an option. Unobserved concurrent use and rounded percentages can add noise even on an unshared plan. Fleetctl's usage command reads stored observations; the underlying quota observation must be refreshed around a real batch before the snapshots can measure its consumption.
