# Quota refresh

Quota sources are declared per pool in the overlay. Refresh at the point where usage, selection, dispatch or lease acquisition consumes pool state, so a long session does not route from a stale snapshot.

Each `quota_refresh` block declares an oracle (`codex`, `codex-oauth`, `claude`, `antigravity`, `copilot`, `opencode-go`, `codexbar`, `command`, `file` or `http`), TTL and optional window filter. Null means no percentage source. Pools with no reading and no failed oracle remain UNKNOWN and fail open for routing; measured exhaustion, provider-error circuits and paid caps still refuse dispatch. Bounded paid text uses a cash reservation separately from quota; the existing explicit Gemini route uses an estimate-only cap outside the hard ledger. That cap does not enable automatic admission. See [cash funding](SELECTOR.md#cash-funding-and-owner-envelopes).

Fetch outside the runtime lock, under a nonblocking filesystem claim shared by all callers for one reader and state store. A concurrent caller uses the stored snapshot; manual `codexbar-snapshot` and console refresh use the same claim. Under the runtime lock, replace only with a strictly newer observation. On failure, keep the previous observation and its real age; retry no sooner than the reader's TTL or base cooldown, doubling the delay on repeated errors up to 30 minutes (or the configured TTL if longer). A success resets the failure count. Forced refresh bypasses backoff, not the claim. `glance` still refreshes when stdout is `/dev/null` (the background poll), but skips display and ledger work. Synthetic tests use no-refresh to keep local telemetry out of fixtures.

After an oracle failure, reuse active windows from the last successful reading for at most six hours, marked stale. With no usable reading, the pool state is GAUGE_ERROR. `brief` shows the stale percentage or the error reason; `doctor` reports the failing oracle even when a cached reading is usable. A successful oracle read clears the error. Selection prices GAUGE_ERROR at the greater of `lambda_unknown` and `lambda0` (1.00 by default), so measured pools of similar quality take priority while the failed-gauge pool remains eligible. A trusted 100% window remains exhausted until reset, regardless of age.

Model pools at the metering boundary. One reader can feed independent pools through disjoint window filters; a single fetch serves its due sibling pools. Selection refreshes every candidate pool it consults. Local cost and token telemetry remain estimates, never reconstructed subscription percentages.

A fresh percentage does not clear a circuit opened by a provider quota refusal. Use the supported recovery/snapshot path deliberately; a gauge cannot prove service availability.

HTTP oracles are GET-only and use supported schemes. Bearer credentials must not travel over plaintext. Keep key values out of logs and manifests. Test declarations and independent pool gating before changing quota boundaries or refresh behavior.

AGY Argon uses a separate `antigravity-argon` pool because Antigravity meters its individual allowance in its own bucket, which the shared Gemini windows do not include; the `antigravity` reader records it as `antigravity-quota-summary-argon-weekly`. Flash remains on `antigravity-gemini`; Claude remains on `antigravity-3p`. An AGY `Individual quota reached ... Resets in 1h18m27s` error blocks its lane's pool for the parsed duration, even if its shared gauge is almost unused. Both automatic and manual gauge refresh preserve these AGY refusals until reset. Persistent circuit recording reads the wrapper's own captured output. The legacy empty-output diagnostic may consult a global CLI log, but that uncorrelated fallback does not seed a persistent pool circuit.

A guarded migration may seed a caller-verified refusal as `quota_pools.<pool>.quota_error`, using the same `opened_at`, `until`, `limit_name` and `source` fields as a runtime circuit. The later of the seed and runtime refusal governs admission. These records expire automatically at `until`; they do not imply a measured percentage. `scripts/agy_quota_pools.py --overlay PATH --patch PATCH` prepares and validates an idempotent patch without editing the source overlay. Paid API pools retain explicit-only admission.

OpenCode Go has a built-in reader: `"oracle": "opencode-go"` calls OpenCode's own usage endpoint (`GET https://opencode.ai/zen/go/v1/usage`) with the Go API key and records the 5-hour, weekly and monthly windows, so the pool needs no third-party reader. The optional `key` names where the key lives: an environment variable, an absolute file path or an `op://vault-id/item/field` reference read at refresh time. Without `key`, the reader uses `OPENCODE_API_KEY`, then the Go key OpenCode keeps in its own `auth.json`. The key travels only in the Authorization header. A rejected key, a missing Go subscription and an unreadable answer each come back unavailable with their own reason, so the pool reports GAUGE_ERROR without a usable reading, or its last real percentage marked stale, never an invented 0%. A window OpenCode reports as `rate-limited` counts as 100% used.

The other subscriptions have built-in readers too, in `scripts/native_usage.py`, each using the provider's own tool or the sign-in that tool already keeps. Choose a source whose authentication lifecycle matches how the machine is used:

- `codex` starts `codex app-server`, sends `initialize` and `account/rateLimits/read`, and ends the child's process group. Windows are named by length (`weekly`, `session`), not by slot: Codex currently reports its weekly limit in the `primary` slot and no five-hour limit, and none is invented. A model-specific bucket becomes `<limitId>-<window>` labelled "<model> only".
- `codex-oauth` instead reads Codex's existing ChatGPT sign-in from an owner-only `auth.json` under `$CODEX_HOME` (default `~/.codex`). It calls CodexBar's `GET https://chatgpt.com/backend-api/wham/usage` for the Codex allowance, with no process, proxy, redirect, token renewal or login. This endpoint does not report a separate ChatGPT chat/Pro message allowance. `chatgpt-work` keeps its distinct Pro estimate from the local run ledger and its provider refusal gate.
- `claude` reads `GET https://api.anthropic.com/api/oauth/usage` with Claude Code's own sign-in (Keychain item `Claude Code-credentials`, else `~/.claude/.credentials.json`). It never renews the sign-in, because a renewal would rotate Claude Code's credential: an expired one is reported as such until Claude Code renews it. This source therefore needs a maintained Claude Code sign-in. Windows: `session` (5 hours), `weekly`, and `claude-weekly-scoped-<model>` labelled "<model> only".
- `antigravity` reads an operator export by default. With `reuse_running: true`, it first tries Antigravity's `RetrieveUserQuotaSummary` local RPC on an already-running, same-user Antigravity CLI (`~/.local/bin/agy`) or supported desktop language server. It contacts only discovered listening HTTPS ports on `127.0.0.1`; refresh never launches the CLI or starts sign-in. If there is no usable server, the operator export is the fallback. Legacy `codexbar_widget` flags are ignored. Windows use explicit `gemini`, `3p` (Claude and GPT), and `argon` IDs; `gemini-argon-wtu-weekly` is a distinct Argon bucket, never pooled into Gemini. Unreported buckets are unknown, not zero. A model-level percentage is never substituted for a shared window. This does not prove which bucket a newly added model debits.
- With an explicit `oauth_session_file` on the `antigravity` oracle, read the selected Antigravity ACP/CLI sign-in instead: an absolute path to an existing owner-only session file (`token.access_token`, `token.expiry`). A profile that emits `antigravity-acp/antigravity-oauth-token` can supply that file. Point to the original; do not copy credentials into Crossfeed. This sends only a quota-summary POST to the fixed Google `cloudcode-pa` HTTPS endpoints, with no process, cookie, API key, redirect, credential renewal, or fallback to a different login. The Google endpoint is first-party but not a public versioned API. When the selected file is missing or expired, the reader reports unavailable; normal Antigravity use renews the source outside Crossfeed. Put the same session path on each sibling pool and keep the distinct window filters. Files containing only an ACP refresh token, or vault/keychain-only accounts without an exported access session, are not supported by this option.
- `copilot` reads `GET https://api.github.com/copilot_internal/user` with the GitHub CLI's sign-in (`gh auth token`) or a declared `key` reference, and records the premium allowance (`premium_monthly`) with its monthly reset. Unlimited quotas are not windows.

For a machine that already has working Claude readings in CodexBar, set the Claude pool's `quota_refresh` to `{"oracle": "codexbar", "provider": "claude", "codexbar_source": "web", "ttl_s": 300}`. This pins CodexBar to the existing claude.ai session cookie, without falling through to a CLI probe or depending on Claude Code's OAuth lifecycle. Verify with `fleetctl.py glance`: Claude must have a fresh reading, and its runtime snapshot must name `codexbar` with no Claude refresh error. CodexBar's `isSyntheticPlaceholder` slots are omitted; a placeholder is not measured zero usage. Real unused windows remain visible.

Network and process readers have their own time limits (Codex 20 s, Claude and Copilot 10 s; `timeout_s` overrides). Tokens stay in one request header: never logged, never in a reason, never on disk. A missing tool, a signed-out or expired sign-in, a refusal, a rate limit and an unreadable answer each come back unavailable with their own reason, so the pool shows GAUGE_ERROR or its last real reading marked stale, never 0%.

## Antigravity usage exports

On demand, from an unlocked terminal signed in to the same account as the configured pools, an operator using Antigravity CLI 1.1.11 or newer can capture its JSON `/usage` report. Do not schedule the command or automate sign-in. Publish only after success; the rename prevents readers from seeing half-written output. The export may contain account data: keep it owner-only and out of source control.

```sh
(
  set -eu
  umask 077
  dir="${XDG_CONFIG_HOME:-$HOME/.config}/orchestrator"
  mkdir -p "$dir"
  report=$(mktemp "$dir/.antigravity-usage.XXXXXX")
  trap 'rm -f "$report"' EXIT
  agy -p /usage --output-format json > "$report"
  mv -f "$report" "$dir/antigravity-usage.json"
)
```

The default path is `~/.config/orchestrator/antigravity-usage.json` (respects `XDG_CONFIG_HOME`); set an absolute `quota_refresh.path` if needed. The report file's modification time is the capture time, so do not retimestamp old reports. Crossfeed rejects missing, unreadable or more than 15-minute-old reports; an older cached reading stays stale at its original capture time and ages out under the existing quota policy. Other pools keep their own refresh schedule.
